# ZhuaTech POS 架构说明

Copyright © 2026 上海如静知华信息科技有限公司。

## 设计目标

社区源码版以“可理解的零售交易闭环”为目标，将高频、低延迟的门店收银界面和重查询、重分析的后台管理界面分开建设，同时共享订单、商品、会员、门店与身份模型。

## 分层结构

```text
Browser
├── Cashier workspace  /cashier/*
└── Admin workspace    /admin/*
        │
        ▼
Spring Security → REST Controller → Application Service → JPA Repository
                                                        │
                                                        ▼
                                                    MySQL 8.4
```

- `controller` 负责 HTTP 协议、输入校验和权限声明。
- `service` 负责结账、库存扣减、优惠校验和经营指标聚合。
- `repository` 负责实体查询，不承载业务判断。
- `model` 使用 `pos_` 表前缀，避免与 ERP、OMS 等系统表冲突。
- `security` 使用无状态 JWT；实际生产应叠加设备身份和密钥轮换。

## 结账一致性

`PosService.checkout` 在单一数据库事务中完成商品校验、库存扣减、优惠校验、主订单和订单明细保存。社区版使用单库事务便于学习；高并发生产方案还需要库存版本号或原子扣减、请求幂等键、支付状态机、消息投递表和失败补偿。

## 双端职责

| 收银用户端 | 后台管理端 |
| --- | --- |
| 商品录入、购物车、会员识别、促销结果、收款、订单、交班 | 经营指标、商品、订单、门店、会员、营销、报表与审计 |
| 优先保证操作路径短、状态明确、可键盘/触屏操作 | 优先保证数据口径、筛选能力、跨门店比较和异常处理 |

## 扩展建议

获商业授权并进入生产化阶段后，可增加支付适配层、设备网关、促销领域服务、会员账本、离线交易队列、消息中间件、Redis 缓存、数据仓库和审计中心。所有真实会员与支付信息均应遵循最小收集、加密存储和授权访问原则。
